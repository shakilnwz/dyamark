# Report: UI review of dyamark 1.0.0

Date: 2026-10-28

**Question:** where does dyamark's interface fall short, and what should be
fixed first?

**Short answer:** the diagrams are the strongest part; the basics around
them are the weak spots. All the high findings are fixed. 16 findings open:
11 medium, 5 low.

## Method

- Rendered 16 screens offscreen at 1200 × 800 with the real drawing code
  (`gioui.org/gpu/headless`): the sample shown with no file, and a test
  document with every block type (headings, a paragraph with bold, inline
  code, a link and emphasis, nested and ordered lists, tasks, a quote, a
  table, a Go code block, a sequence diagram with autonumber, `alt` and a
  note, a broken diagram, a flowchart). States covered: view, keyboard
  focus on a diagram, 150 % text, a 520 px window, the viewer, the viewer
  scrolled with the pinned row, edit, split, and the unsaved-draft prompt.
- Themes: the current Omarchy theme (snxz, dark) and Catppuccin Latte
  (light).
- Read the input-handling code for what screenshots can't show, such as
  which keys work.
- **Limits:** the renders use only the bundled fonts, so emoji and other
  scripts that system fonts would supply show as boxes. The app wasn't used
  in a real window.

## Fix these first

1. **Four quick visual fixes:** task checkboxes (R4), tab characters (R5),
   sequence-number contrast (D1) and the pinned row (D2).
2. **The `?` shortcut overlay** (G1), already planned for phase 7, plus a
   small viewer info line (V1).

## Reading documents

### R3 · Medium · No scrollbar or position cue

Neither the view nor the editor shows where you are in the document or how
long it is.

- **Fix:** a thin `material.Scrollbar` beside the list, and one for the
  editor.

### R4 · Medium · Task items show a bullet and a box

Each task gets the list bullet and then a box glyph. The filled `■` for a
done task reads as a second bullet rather than a ticked box.

- **Fix:** draw a vector checkbox in the bullet's place (an outlined
  square, with a tick when done) and dim the text of done items.
- **Where:** `markdown/inline.go` (the task box text) and the list layout in
  `markdown/blocks.go`.

### R5 · Medium · Tab characters show as a missing-glyph box

Go and Makefile snippets are indented with tabs, and every tab draws as a
small box in code blocks and in the editor.

- **Fix:** expand tabs to the next 4-column stop when drawing code lines.
  The editor needs separate investigation, since Gio's editor has no
  tab-width setting.
- **Where:** the code block layout in `markdown/blocks.go`.

### R6 · Medium · List numbers run into the text at larger sizes

The marker column has a fixed width. At 150 % text size "1." touches the
item text, and a list that reaches 100 overlaps at any size.

- **Fix:** measure the widest marker in the list and indent by that plus a
  gap.

### R7 · Medium · Keyboard focus on a diagram is easy to miss

`Tab` moves focus between diagrams, but focus looks the same as hover: a
1 px accent outline whose sides are clipped at the column edge, so only two
thin lines show.

- **Fix:** an inset 2 px outline, distinct from hover, and a small "Enter
  to open" hint while focused.

### R8 · Low · Images show only their alt text

`![diagram](arch.png)` becomes the word "diagram" in the paragraph.

- **Fix:** an image block that loads PNG, JPEG and SVG relative to the file,
  scaled to the column.

## Diagrams

### D1 · Medium · Sequence-number digits are hard to read

With `autonumber`, the digits are drawn in the actor fill colour on the
accent circle: 3.89 : 1 contrast at about 9 px in the snxz theme, below the
4.5 : 1 that text this small needs.

- **Fix:** draw the digits in the page background colour (6.49 : 1 here),
  or pick black or white by the accent's luminance.
- **Where:** `seq/draw/draw.go`, the `m.Number` block (uses
  `seqTh.ActorBkg`).

### D2 · Medium · Pinned participant row is see-through and too tall when zoomed

The pinned row's background is slightly transparent, so messages scrolled
under it still show through. It's also drawn at the diagram's zoom: at
180 % it takes about 165 px, a fifth of the window.

- **Fix:** make the strip opaque, and cap the pinned row's scale so it
  stays around 56 px tall however far you zoom in.
- **Where:** `app/viewer.go` `drawStickyActors`.

### D3 · Medium · Diagram errors ignore the theme and don't lead to the source

The error box uses fixed reds, so it looks foreign in light themes. Its
text is smaller than body text. It gives two different line numbers,
"markdown line 64" and "line 2", for the same mistake. It doesn't show the
broken line or offer a way to jump to it.

- **Fix:** use the theme's red (`color1`) for the border and a tint of it
  for the fill. Give one file line number, quote that line, and add "E to
  edit"; the viewer's `E` already knows how to jump to a line.
- **Where:** `markdown/blocks.go`, the error drawing (fixed `color.NRGBA`
  values).

### D4 · Low · Activation bars are see-through

The bar is the accent at low alpha, so the lifeline's dashes and frame
labels show through it. Mermaid fills it solid.

- **Fix:** mix the accent into the background to get an opaque colour,
  rather than lowering alpha.
- **Where:** `app/theme.go`, `ActivationBkg`.

### D5 · Low · The mmdc render hint is a shouted label, not a button

"FLOWCHART — PRESS 'R' TO RENDER WITH MMDC" is all caps in the accent
colour. There's nothing to click, and which block `R` renders depends on
where the pointer is.

- **Fix:** a quiet type label ("flowchart") and a small "Render" button in
  the block's header, with `R` as its shortcut.

## Diagram viewer

### V1 · Medium · The viewer gives no orientation

The viewer is the diagram alone: no title, no "2 of 3", no zoom level, no
hint that `[` `]`, `N`, `E`, `W` and `H` exist. The clean look is right,
but someone new has no way in.

- **Fix:** a small line in a corner, "Checkout flow · 1 of 2 · 100 % · ?
  keys", that fades after a couple of seconds and comes back on zoom or a
  key press. The focus hint added in phase 6 already uses this style.

## Editing

### E3 · Medium · No find in the view or the editor

There's no `Ctrl+F`. Looking for a participant or an endpoint in a long
spec means scrolling.

- **Fix:** a find bar that searches the source, highlights matches in the
  editor, and in the view scrolls to the block containing the next match.

### E4 · Low · Editor has no line numbers or current-line highlight

Diagram errors report line numbers, but the editor shows none, and the
caret's line isn't marked. Syntax colouring is already planned for later.

- **Fix:** a muted line-number gutter and a faint band behind the caret's
  line.

### E5 · Low · Prompts sit on a busy, lightly dimmed page

The page behind a prompt is dimmed only a little, and the card has no edge,
so in dark themes it blends into the diagram underneath. The keys and
buttons themselves work well.

- **Fix:** dim more (around 80 %) and give the card a 1 px border in the
  accent at low alpha.

## Across the app

### G1 · Medium · No shortcut list in the app

The keys are listed in the README and in the sample document shown with no
file, nowhere else. Several important actions (split view, the viewer
keys, focus) have no on-screen hint.

- **Fix:** the `?` / `F1` overlay planned for phase 7, grouped by mode,
  using the prompt's card style.

## What works well

- Sequence diagrams match Mermaid and stay crisp at any zoom.
- The reading column (860 px) and heading scale give long text a good line
  length and rhythm.
- Omarchy themes carry through: the light Catppuccin Latte render is as
  readable as the dark one.
- Tables are clean: header row, banding, wrapping inside cells.
- Focus mode in the viewer dims precisely what it should, including the
  pinned row.
- Prompts are fully keyboard driven, with the key shown on each button.

## Suggested order

1. **Quick fixes, about a day:** R4 task checkboxes, R5 tabs, R6 list
   markers; D1 badge contrast, D2 pinned row, D4
   activation fill; R7 diagram focus, E5 prompt dimming.
2. **Orientation, with phase 7:** G1 shortcut overlay, V1 viewer info
   line; R3 scrollbars, D3 error box, D5 render button.
3. **Bigger features:** E3 find, R8 images, E4 editor gutter.
